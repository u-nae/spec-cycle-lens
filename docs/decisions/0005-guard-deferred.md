# 0005 편집 가드는 3단계에서 warn만 검토하고, 착수 전 결정 기록을 남긴다

- 상태: 확정 (PRD v0.2 Q5, 2026-10-27)
- 날짜: 2026-10-27

## 맥락
활성 작업 항목이 `in-progress`가 아닐 때 소스 파일 편집을 경고하거나 막는 가드(PRD §6.10)를 넣을지 정해야 했다.
spec-cycle의 원칙은 "hook 자동화 없음, 모든 진입점은 사람이 호출"이다. 가드는 이 원칙과 긴장 관계에 있다.

## 결정
MVP(2단계)에는 넣지 않는다. 3단계에서 `warn`(toast만, 결정에 관여하지 않음)만 검토하고, `ask`는 검토하지 않는다.
착수 전에 별도 결정 기록을 작성한다. 기본값은 `off`다. 에이전트 권장안: 이 안 (채택 여부: 채택)

## 대안
- MVP에 `warn` 포함: 구현은 작지만 원칙 검토 없이 자동화가 들어간다.
- 영구 제외: 안전하지만 게이트 밖 편집을 알아챌 기회를 버린다.

## 영향
- `userConfig.guard`는 3단계 전까지 선언하지 않는다. A19(`gatingHooks` 비어 있음)가 MVP 수용 기준으로 남는다.
